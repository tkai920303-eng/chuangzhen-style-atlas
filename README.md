# 素材风格图鉴 · Style & Motion Atlas

> 视觉风格、动效语言、光影布光——三个**可以直接复制使用**的参考库。
> 每一条都带参考图与成品提示词；每一条都能一键复制。

> ⚠️ **许可范围**：`LICENSE` 只覆盖本仓库的**代码与自产内容**；图片素材**逐条授权不同，不适用 MIT**。
> 引用任何一张图之前，请先看 [`NOTICE.md`](NOTICE.md) 与 [`docs/图源署名.md`](docs/图源署名.md)。

一个零第三方依赖的本地素材库：克隆下来 `npm start` 就能用，不需要数据库、不需要构建、不需要联网。

---

## 三个库

| 库 | 条目数 | 解决什么问题 | 参考图 |
|---|---|---|---|
| **风格库** `styles` | 552 | 这个画面长什么样：画面 / 配色 / 动法 / 光影四位一体 | 552 张，逐条有图 |
| **动效库** `motions` | 370 | 这个动效怎么动：时序、缓动、幅度三段参数 | 370 张，218 条带**循环动图** |
| **光影库** `lighting` | 130 | 光打在哪、软不软、比多少、多冷 | 130 张，含自产布光示意图 |

### 风格库 552 条怎么来的

- **本地 24 条** —— 自己已经沉淀的风格体系（逐帧手绘、等轴 2.5D、扁平矢量、线条动画、3D 渲染……）
- **atlas 504 条** —— [Atlas of Visual Effects](https://atlas.letz.ai)，按历史年代（1820s–2020s）与机器章节（边缘与特征 / 遮罩与控制 / 色彩与量化 / 印刷与抖动 / 视频与故障 / 空间与光学 / 滤镜与运动 / AI 管线）分类
- **motion-prompt 24 条画风** —— 水彩、油画、水墨、浮世绘、点彩、Risograph、波普、霓虹、Art Deco、像素、体素、低多边形、刺绣、Synthwave、蓝图……

每条都是七段式提示词：`【画面】【配色】【动法】【光影】【质感】【适用】【限制】`。

**配色不是手填的**——是用 ffmpeg 从每一张参考图里实际解码、量化提取出来的。

### 动效库 370 条怎么来的

- **本地 130 条** —— 工程内已实现的动效与组件（16 条动效 + 114 条组件源码），**只引用不搬动**，保持原工程路径可用
- **motion-prompt 240 条** —— 10 个包 × 24 条：动效图形、镜头运动、UI 组件、LP 图形、摄影、动效图形（第二弹）、LP（第二弹）、镜头（第二弹）、画风、图表

**白模化**：240 条全部生成了「白模版」——只继承运动学（时序 / 缓动 / 幅度），外观全部换成中性灰白哑光（`#e8e8e8`）+ 1px 浅灰描边 + 单层接触阴影，规格里的颜色词统一替换成 `{颜色}`，并留出 6 个可替换槽位（主体形状 / 材质 / 主色 / 背景 / 投影 / 文字）。先在白模上验证节奏，再套具体风格的配色与材质。

### 光影库 130 条怎么来的

- **atlas 69 条** —— 空间与光学、光影效果
- **motion-prompt 8 条** —— 逆光、轮廓光、剪影、分割光、伦勃朗光、蝴蝶光、黄金时刻、蓝调时刻
- **全网 53 条** —— XO3D 24 套布光方案 + 光影术语 6 条 + 自然光 15 条 + 人物光位 8 条

## 快速开始

```bash
git clone https://github.com/tkai920303-eng/chuangzhen-style-atlas.git
cd chuangzhen-style-atlas
npm ci           # 运行时零依赖；playwright-core 仅供预览渲染工具使用
npm start        # → http://127.0.0.1:5178
```

打开 <http://127.0.0.1:5178/atlas> 就是**视觉参考图鉴**：三个页签、分类筛选、全文搜索，点条目开抽屉看详情。

**图鉴也可以直接双击打开**：`server/public/atlas.html` 是单文件自包含 HTML（零外部脚本与链接，数据全部内联），用 `file://` 打开时会自动改走相对路径读本地图片。

### 索引你自己的作品

这个仓库**只提供参考库**。你自己的作品是另一回事——用仓库自带的扫描器索引它：

```bash
npm run scan -- "D:/你的作品目录"    # 扫描并生成索引（只读，不移动任何文件）
npm start                            # 然后打开 http://127.0.0.1:5178/myworks
```

- 扫描根下的**一级子目录**各算一个作品；自动跳过 `node_modules`、`.git`、构建产物等目录
- 产物写在仓库根目录的 `我的作品/`（`index.json` / `works.json` / `summary.json`）
- 该目录已在 `.gitignore` 里，**你的作品不会被提交进这个公开仓库**；
  `npm run verify` 有断言守着这条线
- 有 `ffprobe` 就顺带探测视频时长与分辨率，没有就只记文件元数据

### 一键复制

| 位置 | 按钮 | 复制的内容 |
|---|---|---|
| 风格库条目 | 复制风格配置 | 七段式风格提示词 |
| 风格库条目 | 复制效果指令 | Atlas 原始效果指令 |
| 动效库条目 | 复制动效提示词 | 可直接问 AI 的动效描述 |
| 动效库条目 | 复制白模版 | 去风格化的白模提示词 |
| 动效库条目 | 复制元素代码 | motion-prompt 的 MIT 元素代码（首行授权注释保留） |
| 光影库条目 | 复制光影提示词 | 光位 / 光质 / 光比 / 色温 |
| 顶栏 | 复制筛选清单 / 复制全部提示词 | 当前筛选结果 / 全库 |

## 怎么用起来

### 网页上用

`npm start` 后打开 <http://127.0.0.1:5178/atlas>，点条目开抽屉即可复制提示词。

### 命令行检索（不开服务）

```bash
npm run search -- styles bloom --limit=3      # 风格库按关键词
npm run search -- motions pop-in --cat=镜头运动 # 动效库 + 分类
npm run search -- lighting 逆光                # 光影库
npm run search -- motions --list-cats          # 先看有哪些分类
npm run search -- styles bloom --json          # JSON 输出，供脚本消费
```

输出会连带打印来源、授权与**可再分发标记**。

### 给 AI Agent 用

仓库根目录的 **`skill.md`** 就是给 Agent 的说明书：写清了数据在哪、怎么检索、哪个字段干什么、
参考图怎么取、以及**授权红线**。支持文件读取的 Agent 装上即可用，不需要理解本项目结构。

```bash
# 常见的几种装法
cp skill.md <agent-skills-dir>/style-atlas/SKILL.md
# 或直接在提示里贴给 Agent：读取本仓库的 skill.md 并按它工作
```

### HTTP 接口

```
GET /api/atlas                    三库概要
GET /api/atlas/styles             风格库（?q= 搜索 &cat= 分类过滤）
GET /api/atlas/motions            动效库
GET /api/atlas/lighting           光影库
GET /atlas-img/<目录>/<文件>       取参考图
```

完整用法见本 README 的「怎么用起来」，以及给 Agent 用的 [`skill.md`](skill.md)。

### 本地 130 条在分发包里的状态

这 130 条来自作者自己的工程（16 条动效 + 114 条组件源码）。**分发包只带参考图与元数据，不带源码**：

- `assets/动效参考图/` 的 130 张规格卡里写明了源码位置、依赖与状态，是这批条目唯一的可核对依据
- `data/动效库.json` 中这些条目的 `sourcePath` **已脱敏**：本机绝对路径统一替换成 `<私有工程>/…` 相对示意路径
  （保留文件名与调用点 `#符号`，去掉盘符、用户名、AI 工程 ID 与内部目录）。规则见 `tools/脱敏.mjs`
- 克隆者拿到的是「这个效果叫什么、在哪个文件里、需要哪些参数」——不是可执行链接，也无法反推作者的目录结构
- 其中 2 条有真实渲染实拍（`FX-KIT-PARTICLES-001`、`FX-ML-SHUTTER-001`），包内提供的是已渲染好的海报帧与循环动图；原始 mp4 不随包分发
- 想在自己的工程里用这批条目，按规格卡上的参数自己实现即可；`tools/预览渲染/` 里的渲染器可复用

## 重新构建

```bash
npm run fetch          # 抓 atlas 504 条 + motion-prompt 240 条 + 渲染包
npm run fetch:artstyle # 抓 24 张画风卡
npm run palette        # 从全部参考图提取配色（需本机 ffmpeg）
npm run build          # 组装三个库 JSON
npm run build:atlas    # 生成单文件图鉴
npm run verify         # 校验结构、引用与产物
npm run smoke          # 启动服务，跑页面 / 接口 / 参考图 / 目录穿越断言
```

预览图与示意图需要本机 Chrome（渲染器走 CDP 管道，不占调试端口）与 ffmpeg：

```bash
npm run render:motion    # 216 条动效 → 静态海报帧 + 循环动图
npm run render:lighting  # 53 张布光示意图
npm run render:card      # 130 张规格卡
npm run render:verify    # 用 ImageDecoder 逐个校验动图帧数
```

> `playwright-core` 已在 `devDependencies` 里，`npm ci` 会装好；它只用于渲染工具，运行服务本身零依赖。

> Windows 下若 `ffmpeg` 不在 PATH，设 `FFMPEG_PATH`；Chrome 路径不同则设 `CHROME_PATH`。

## 这个包和本地库的关系

这个仓库是**本地素材库的公开子集**，不是全量搬运：

| | 本地库（不公开） | 本仓库（公开） |
|---|---|---|
| 规模 | 全量素材（14 万+，300+ 作品） | 公开子集 —— **本次导出的文件数、体积、三库条数、参考图数见 [`docs/同步状态.md`](docs/同步状态.md)** |
| 内容 | 全量索引 + 私有工程路径 + 第三方原片 | 三个参考库 + 全部参考图 + 采集/构建脚本 + CI |
| 隐私 | 保留本机路径 | 全部脱敏为 `<私有工程>/…` |
| 你的作品 | 属于你，不在这里 | 用 `npm run scan` 在你本地索引，**永远不入库** |

三库（风格 552 / 动效 370 / 光影 130）与参考图会随本地库一起增长，
每次发布都会**重新导出并跑完整验收**，包内 `docs/同步状态.md` 记录了本次导出对应的
本地库规模与生成时间——用它可以对上「包有多新」。

同步入口是**维护者私有素材库**里的 `04_工具\同步开源包.mjs`（不在本仓库内）：一条命令完成
**重新导出 → 验收 → 泄露扫描 → 与上一版逐文件比对 → 输出变更清单**。
克隆者不需要它——本仓库本身可以直接 `npm run build` 重建。

### 这个仓库里**没有**什么

| 不含 | 为什么 |
|---|---|
| 任何个人作品库（成片、工程文件、第三方原片） | 这是**参考库**，不是作品库；个人内容属于你 |
| 本机绝对路径与用户名 | 全部脱敏为 `<私有工程>/…`；`npm run verify` 与泄露扫描逐条断言 |
| 54 张版权保留的 atlas 主图 | 构建时自动剔除；条目、提示词与署名完整保留 |
| 第三方素材 | 按路径 + SHA-256 + 引用三道防线剔除，清单见 `data/third-party-exclusion.json` |

## 设计取舍

1. **配色靠提取，不靠手填** —— 手填的色板和参考图对不上，等于没有依据。全部色板从图片实解码。
2. **白模只继承运动学** —— 外观全部中性化，避免风格锁死；可替换槽位写死在白模版里。
3. **图鉴单文件自包含** —— 数据内联、零外部依赖，双击就能看，也能直接部署到静态托管。
4. **规格卡而不是假预览** —— 本地工程条目没有独立渲染预览，就老老实实给规格卡（源码位置、参数、依赖、状态），不编造画面。
5. **同一套脚本两种布局** —— `tools/paths.mjs` 识别目录特征，本地开发态与发布包态共用同一份采集/构建代码。
