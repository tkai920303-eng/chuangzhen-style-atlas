# 改动说明 · 修复发布包内的作品名泄漏与审计盲区

日期：2026-11-23
范围：作品名脱敏链路（`04_工具/脱敏.mjs`、`04_工具/导出开源包.mjs`、`04_工具/审计发布包个人内容.mjs`）
状态：**本地已完成，未提交、未发布**

> ⚠️ 本文件会随包分发，内容已按脱敏口径处理，不含任何本地作品名。

## 背景

复核 atlas 主图授权时发现，发布包里仍然带着**本地作品名**。
文件名、路径、提示词、署名都规规矩矩地脱敏了，但**作品名本身**从三个地方漏了出去。

实测（修复前）：发布包 1190 个文件里命中 **33 处**本地作品名，分布在 3 个文件：

| 位置 | 泄漏了什么 |
|---|---|
| `tools/库源/第三方素材.json` | 第三方剔除清单里的**完整相对路径**，路径中段就是作品名 |
| `docs/改动说明.md` | 正文里点名的作品 |
| `docs/改动说明_定稿与同步.md` | 正文里点名的作品 |

素材本体（成片、音频、图片）确实没有随包——三道防线一直是有效的。
但**作品名本身也是个人信息**：它能反推出作者做过哪些项目、正在做哪些拆解。

## 根因：三个缺口

### 1. 作品名名单只取了一半

`导出开源包.mjs` 的作品名脱敏器只从 `03_索引\works.json` 取名。
而 `works.json` 登记的是**工程类**作品（本地各工程目录），**素材库类**作品——第三方原片的
拆解产物——**一条都不在里面**。

实测这批名字 `isDistinctiveWorkName` 全部判定为「有辨识度」，
也就是说名单机制本来就能识别它们，**只是取名单的地方漏了一个来源**。

### 2. 文档脱敏链路根本没接上作品名脱敏

`copyDocSanitized()` 只做机器信息正则脱敏（盘符路径 / PID / 端口），
从头到尾**没有调用** `sanitizeWorkName()`。
所以改动说明里的作品名一直原样随包分发。

### 3. 剔除清单被原样拷贝

`tools/库源/` 整个目录被 `copyDir` 原样复制，剔除清单的 `paths` 数组没有任何处理。

## 修复

### 1. 统一的作品名清单（`04_工具/脱敏.mjs`）

新增 `collectLocalWorkNames(root)`，合并两个来源：

1. `03_索引\works.json` —— 工程类作品
2. `02_素材` 下的作品目录（`视频库` / `创作资料库` / `音频库` / `图片库/第三方参考图`）——
   素材库类作品；同时剥离 `_原片画面拆解报告` / `_画面设计拆解包` / `_原片字幕与拆解报告` /
   `_文案拆解包` 等后缀，取到作品本名

发布包布局下没有这两个目录，函数返回空表，调用方静默跳过。

### 2. 导出端接上作品名脱敏

- 导出脚本改用 `collectLocalWorkNames(LIB)`（308 个名字，原为 309 个工程类名字）
- `copyDocSanitized()` 在正则脱敏之后**追加作品名脱敏**
- `tools/库源/第三方素材.json` 的包内副本逐字段脱敏；**本地那份保持真实路径不动**——
  导出的路径防线依赖它，不能动

### 3. 审计门禁补上同一份名单

`审计发布包个人内容.mjs` 原先也只读 `works.json`，改成用同一份 `collectLocalWorkNames(LIB)`。
**导出端与审计端必须用同一份名单**，否则审计就是自说自话。

## 验证

**门禁修复后的即时验证**——不改任何内容、只换审计脚本，扫修复前的包：

```
❌ 命中本地作品名 33 处
   docs\改动说明.md ← … | docs\改动说明_定稿与同步.md ← …
❌ 1 项未通过（退出码 1）
```

与独立探针（直接扫 `02_素材` 目录名）得到的 33 处**完全一致**，证明盲区已关闭。

重新导出后：

- 泄露扫描：1190 文件，**命中 0**，占位符 0
- 个人内容审计：**全部通过**（含作品名一项）
- `verify` / `smoke`：全部通过

## 另一件要报告的事：库被并发写入

复核期间发现**另一个会话正在往这个素材库写新素材**（第三方原片的拆解产物），
导致本地第三方剔除清单从 10 个条目增长到 12 个。

处理方式：

- 本次导出会把新增的 1078 个文件一并纳入剔除范围（清单驱动），发布包的第三方内容边界**更严**了
- 导出末尾的残留断言与 `smoke` 的整包 SHA-256 复核都通过，包内第三方素材字节命中 0
- 新素材的名称**没有**进入包内（只出现在「被剔除」清单里，且清单已脱敏）

但这说明**这个库当前有并发写入者**。本次的三库重建逐条 diff 显示非授权字段差异 0 处，
重建本身没有被并发写入污染；不过后续如果还有并发写入者，
建议先确认所有权再动索引。

## 没有变的部分

- 素材本体（成片、音频、图片、第三方原片）的三道防线不变
- 作品名脱敏的放行规则不变（普通英文单词、集数编号仍放行）
- 本地库的第三方清单保留真实路径，导出仍靠它做路径防线
- 本次改动**未提交、未发布**
