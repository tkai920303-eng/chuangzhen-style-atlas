## 背景

素材库里已经有三库（风格 / 动效 / 光影），此前的内容主要来自两个公开数据源
（atlas 的 504 条视觉特效、motion-prompt 的 240 条动效）以及一批工程内组件。
它们能回答「这个效果怎么写提示词」，但缺一类东西：**成片级的画面系统是怎么搭的**。

这一轮补上的，是把 9 条第三方短视频**逐镜逆向拆解**之后的成果重新抽象成可复用条目：
每条片子拆出 10～84 个镜头，标注画面构成、叙事作用、组件、配色，
再从中归纳出「这类片子普遍用哪几套底纹 / 哪几个转场动效 / 哪几种布光」。

结论单独沉淀进三个库，而不是塞进第三方内容库——因为它是**方法论**，不是素材。

## 授权边界（这一轮最要紧的事）

拆解对象是第三方作品，**它们的像素、音轨、字幕、文案一律不随包再分发**。
所以这一轮新增的 17 张参考图，**全部是自产的**：

| 内容 | 来源 | 处置 |
|---|---|---|
| 条目文本（画面构成、动法、光影、限制、混搭边界） | 自撰的方法论归纳 | 入库，随包分发 |
| 提示词与白模版 | 自撰 | 入库，随包分发 |
| 动效元素代码 | 自撰（MIT 标注） | 入库，随包分发 |
| 17 张参考图（6 风格 + 6 动效规格卡 + 5 光影示意图） | **PIL 自绘**，不含任何第三方像素 | 入库，随包分发 |
| 原片画面 / 音轨 / 字幕 / 角色 / 书法 logo / 历史照片 | 第三方作品 | **不入库、不外发** |

参考图是**按设计特征重画**的示意图（点阵底纹、星芒章节卡、聚光锥、边缘轮廓光……），
不是原片截图。自产脚本是 `04_工具/生成画面设计参考图.py`，重跑即覆盖同名文件，幂等。

## 数据源与构建方式（为什么不是直接改索引）

`04_工具/构建三库.mjs` 是**全量重建器**：它从 atlas / motion-prompt / 组件库等源重新拼出三个索引。
直接改 `03_索引/*.json` 会在下次重建时被清空。

所以新增条目放在 `04_工具/库源/画面设计沉淀.mjs`（数据源），
由构建脚本在三处各加一段合并：

- 风格段：走与「本地已有风格」同一套字段与 `paletteFrom` 机制；
- 动效段：条目自带完整代码与白模版，不走 components.json 的「瘦字段」路径；
- 光影段：条目自带完整参数，不依赖外部资料条目。

**单一构建入口，重建不丢。** 条目的 `sourcePath` 指向这个数据源文件，
并且**随布局变化**：本地是 `04_工具/库源/…`，发布包是 `tools/库源/…`，
包内用户按 sourcePath 也能找到文件。

## 索引基线可刷新了

`04_工具/校验索引一致性.mjs` 第 4 节拿基线哈希当「重扫有没有偷偷改库」的哨兵，
但基线是一次性快照——只要库里有**有意**的变更（新增条目、授权判读刷新），
哨兵就一直报红，下一个会话分不清「数据变好」和「数据被破坏」。

新增 `04_工具/刷新索引基线.mjs`：有意改库之后跑一次，把哨兵挪到当前状态；
校验脚本改为**自动挑最新的基线目录**（按目录名里的日期排序，不按字典序——
`索引基线_20261123` 和 `索引备份_重扫前_20261119` 按字典序会挑错）。
旧基线目录保留不删，是历史证据。

## 顺带补齐：GFDL 许可全文

这一轮核对发布包时发现一个**上一版就存在**的许可缺口：

`NOTICE.md` 的判读表里写着 GFDL 2 条「可再分发，但需附 GFDL 全文并同授权」，
而这 2 张主图（`kaleidoscope`、`mirror-repeat`，来源 GIMP Documentation Team）
**确实随包分发**——但 **GFDL 全文没有跟着进包**。许可不完整。

补法：

- `docs/GFDL许可全文.txt` —— GNU Free Documentation License v1.3 全文，随包分发；
- `NOTICE.md` 增加「GFDL 主图：许可全文随包分发」一节，写清这 2 张图
  **不适用仓库的 MIT、仍按 GFDL 分发**，引用时须连同全文一起带上；
- `npm run verify` 增加断言：**GFDL 主图随包时，`docs/GFDL许可全文.txt` 必须存在**；
- 导出脚本把这份全文从模板复制进包（与 vibe 引擎的 6 份 OFL 字体许可同一套路）。
