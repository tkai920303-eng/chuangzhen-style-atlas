## 背景

素材库里已有三库（风格 / 动效 / 光影）与两个第三方内容库（文案拆解、画面设计拆解），
但**缺一类东西：一条知识短片「从头怎么做」的方法**。

现有内容能回答「这个效果怎么写提示词」「这条成片的画面系统怎么搭」，
回答不了「一句文案出来，屏上该演什么」「这镜头怎么接」「这套配色在全片里各自代表什么」。

`vibe-knowledge-film`（GitHub 开源 Skill，MIT）正好补这一块：它把抖音「Vibe 知识大赏」
这类无旁白知识短片的做法拆成了可执行规则——**六种画法**、**画面语法**、**两套外观规格**、
**分镜表格式**，外加一套可复用的渲染引擎与件库。

## 许可边界（这是本轮最要紧的事）

上游仓库自己的许可声明是**分段**的：

> 引擎、脚本和文档里的方法说明使用 MIT 许可，见 `LICENSE`。
> `references/analysis.md`、`references/prompts.md` 里按成片填好的 brief，
> 以及 `examples/stim_B`、`info_C`，字幕和画面设计来自他人的短片，版权属于原作者。

所以这个仓库**不能整包当成 MIT 搬进来**。而且那句 MIT 授权是**枚举式**的——
只授权「引擎、脚本和文档里的方法说明」，`examples/` 下的图并没有被点名。
上游自己的 `examples/README.md` 也写着「能带走的是做法，不是画面」。

据此把上游内容分成四档：

| 上游内容 | 判定 | 本地库处置 | 公开包处置 |
|---|---|---|---|
| `engine/vk.js`、`engine/vk-kit.js`、`LICENSE`、6 份 OFL 字体许可 | MIT（上游明文授权） | 入库 | **随包分发** |
| `references/*.md`（5 份方法说明） | MIT，但**成段引用他人短片的字幕原句** | 入库 | **不随包分发**——方法结论已转述进索引条目 |
| `examples/` 的样片拼图（4 张）与样例分镜表（2 份） | **上游 MIT 未列举**，无再分发授权 | 入库 | **不随包分发** |
| `references/analysis.md`、`references/prompts.md`、`examples/stim_B`、`examples/info_C` | 字幕与画面设计**属原作者** | 只入本地对照目录 | **不随包分发** |

另有两处**特意没搬**：

- `examples/stim_B/index.html` 与 `examples/info_C/index.html` 是通用渲染外壳，
  与 `engine/index.html` **字节完全相同**（SHA-256 `7222a643adae01a2…`），不含受限内容，
  引擎目录已有一份，不重复收录——否则同一份内容在库里会以「MIT」和「受限」两种身份出现，自相矛盾；
- `fold_C.gif`、`pigeon_B.gif` 两个成片样例共 47 MB，是「看效果」用的成片，不是拆解参考素材。

## 纳入公开包的范围

**决定纳入**。理由与前两个库不同：文案拆解库、画面设计拆解库不放包是因为**授权受限**，
而本库的**方法结论是干净的 MIT**，对公开仓库的价值也高——它回答的是「怎么把一条片子做出来」。

| 位置 | 内容 |
|---|---|
| `data/Vibe画法库.json` | 26 条方法条目（导出时剥除本地库路径字段与参考图引用） |
| `data/vibe件清单.json` | VKit 25 件 + VK 核心 API 21 项 |
| `tools/检索Vibe画法.mjs` | 离线检索（两层命中 + `--kit` 件清单 + `--json`） |
| `tools/vibe引擎/` | `vk.js` + `vk-kit.js` + MIT `LICENSE` + 6 份 OFL 原文 + 引擎说明 |
| `server/public/atlas.html` | 图鉴新增第 4 个页签「Vibe 画法库」 |
| `server` 接口 | `/api/atlas/vibe`，搜索面含 `theme` / `kind` / `detail` |

**不纳入**：上游 `references/*.md` 原文（通篇引用他人短片字幕原句，逐句剥离会破坏结构）、
上游 `examples/` 下的样片拼图与样例分镜表（上游 MIT 未授予再分发）、
Python 渲染管线（需 Python + Playwright + Chrome + ffmpeg，与「clone 即用、不联网」的承诺冲突）、
全部版权受限内容。

因此**包内没有 Vibe 的参考图**：条目以「文字规则 + 配色 token」呈现，
图鉴页签里显示的是分类占位块，不会有破图。

## 第三方清单

清单从 17 条目增至 **19 条目**，本轮新增三条（口径各不相同，分别登记，不一律写成「未授权再分发」）：

|---|---|---|
| `tp-vibe-knowledge-film-restricted` | `版权受限_仅本地对照` | 未授权再分发 |
| `tp-vibe-knowledge-film-docs` | 5 份方法文档 + 2 份样例分镜表 | MIT（上游自述）；本包不再分发——文中逐句引用他人短片的字幕原文 |
| `tp-vibe-knowledge-film-images` | `图片库/知识短片参考图` | 未授权再分发（上游 MIT 只覆盖引擎 / 脚本 / 方法说明，未列举 `examples/` 下的图） |

导出时按既有的三道防线处理：**路径命中即删、内容 SHA-256 比对即删、引用置空**。
导出末尾的全包残留断言会在有残留时直接让导出失败。

包内 `tools/库源/第三方素材.json` 的路径中段已脱敏为 `<私有工程>`；
`source` 与 `reason` 里保留 `vibe-knowledge-film` 的项目名与上游许可原文——这是**归属与排除说明**，
点名一个公开开源项目不属于泄漏。

- 引用代码与文档时**带上上游出处** `HeyChengC/vibe-knowledge-film`（MIT）；
- 分发引擎件时**带上 `tools/vibe引擎/LICENSE`** 的 MIT 声明，字体带上同目录的 OFL 文本；
- `版权受限_仅本地对照/` 里的字幕与画面设计**不得**当成自己的作品发布；
- 上游 `examples/` 下的图**没有再分发授权**，转发前请直接取上游仓库。
