### 1.2 动效库 240 条怎么补上的

`showheyohtaki/motion-prompt` 官方仓库**只有 46 个媒体文件**，没有逐条预览图，
所以没有现成图可下载。采用的办法是**在本机执行作者的绘制函数自渲染**：

- 作者每个包导出 `MotionPrompt.pack(id, factory)`，契约是
  `{width, height, cycle, cells, fonts, images, ready}`，绘制函数签名为 `cells[i](ctx, w, h, u)`，`u` 单位秒
- `04_工具\预览渲染\渲染动效预览.mjs`：加载 10 个 `pack.js` → 逐帧调用 `cells[i]` → Canvas 落帧
- 编码走 **ffmpeg `libwebp_anim`** 输出循环动图（WebP），并自动挑「不透明像素最多」的那一帧做静态海报
- 216 条实际渲染（240 条减去 artstyle 的 24 条画风卡，它们改用作者原图），共 **16,240 帧 / 111.6 秒**
  - PNG 海报 4.54 MB + WebP 循环动图 24.21 MB
- canvas 尺寸 539×208（ui 包 542×191），cycle 4.5–9.4 秒

**格式选型有对照实验**：同一批帧分别编 GIF / APNG / animated WebP，
animated WebP 体积最小（65 KB vs GIF 73 KB vs APNG 152 KB）且支持 alpha，故选它。

**artstyle 的 24 条不重渲染**：作者已提供 MIT 画风卡（`packs/artstyle/img/style-01..24.webp`），
直接作参考图，同时补进风格库与动效库两处引用，不重复造图。

### 4.3 本轮踩到并固化的坑

1. **ffmpeg 没有 libwebp 解码器**（原生 `webp` 解码器不支持动画）
   → animated webp 的配色改由同名 PNG 海报帧提供；动图是否真在动要用 Chrome `ImageDecoder` 读 `frameCount`，
   像素采样不可靠（未挂载 DOM 的 `<img>` 不推进帧）
2. **Chrome 的 `--remote-debugging-port` 回环端口连不上**（进程在 LISTENING，但外部 TCP connect 超时）
   → Remotion / Puppeteer 这类需要调试端口的自动化在本机不可用；改走 **CDP 继承管道**
   （`--remote-debugging-pipe` + 自己实现 transport，漏掉 `rememberEventLoop`/`forgetEventLoop` 会崩）
   → 本轮渲染器直接用 playwright-core 的管道模式绕开
3. **Chrome file:// 测试三坑**：`setContent` 的 about:blank 源加载 file:// 子资源会被拒（页面本身必须跑在 file:// 上）；
   中文路径必须用 `pathToFileURL()`；取 canvas 像素需加 `--allow-file-access-from-files`
4. **Node 的 `http.request` 拒绝路径里的裸中文**（`ERR_UNESCAPED_CHARACTERS`）
   → 冒烟测试里的中文段必须百分号编码，穿越结构保持原样
5. **导出脚本里 `shell: true` + 参数数组**会触发 `DEP0190` 警告 → 改用 `npm.cmd` + `shell: false`

## 五、已知限制

1. **本地 108 条在分发包里只有规格卡与元数据，不含源码**。
   `data/动效库.json` 里这些条目的 `sourcePath` 指向**原作者工程路径**，克隆者无法直接访问
   —— 这是有意保留的溯源信息，不是可执行链接。2 条有实拍的条目（FX-KIT-PARTICLES-001、
   FX-ML-SHUTTER-001）提供的是已渲染好的海报帧与循环动图，**原始 mp4 不随包分发**。
2. **Atlas 的 504 条是「视觉处理/风格」条目，不全是画风**，按历史年代与机器章节分 38 类；
   若只想要纯画风，按 `category` 过滤即可。
3. **motion-prompt 的运动规格只有日文与英文**，时序/缓动/幅度保持英文原文（数值准确，不做不可靠转译）。
4. **atlas 图片逐条授权不同**，商用前必须逐条核对。
5. 动图体积 24.28 MB（218 条），若要进一步瘦身可降帧率重编。

## 七、素材调用方式与 Agent 接入

### 7.1 为什么要单独整理一份调用说明

素材库建完之后，真正的使用方是人（复制提示词）和程序（批量取数），而这两者要的东西完全不同：
人要的是「一键复制」，程序要的是「稳定的字段与路径」，Agent 要的是「**它自己知道去哪儿取**」。
分散在 README、图鉴页和各个脚本里的说明，Agent 读不到也不该读懂。

### 7.2 五种调用方式

| # | 方式 | 入口 | 适合 |
|---|---|---|---|
| 1 | 网页复制 | <http://127.0.0.1:<port>/atlas> 抽屉里的复制按钮 | 人，取单条 |
| 2 | HTTP API | `GET /api/atlas`、 `/api/atlas/<库>?q=&cat=`、`/atlas-img/<目录>/<文件>` | 脚本 / 程序 |
| 3 | 离线检索脚本 | `node 04_工具\检索.mjs <库> [关键词] [--cat=] [--source=] [--json] [--ids] [--full] [--list-cats]` | 人 / Agent 批量 |
| 4 | Agent 接入 | 发布包根目录的 **`skill.md`** | AI Agent |
| 5 | 单文件 HTML | `server\public\atlas.html`（5.9 MB，自包含） | 分享 / 离线看 |

`04_工具\素材调用说明.md` 是这五种的完整说明书，含字段速查、
参考图与配色的取法、授权红线、故障排查表。

### 7.3 新增 `04_工具\检索.mjs`

一个**零依赖、离线可用**的检索 CLI，人和 Agent 用同一套：

- 关键词匹配名称 / 英文名 / id / 分类 / 标签 / 提示词正文
- `--list-cats` 先列分类与条数（`?cat=` 是精确匹配，必须先拿准名字）
- `--json` / `--ids` 供脚本消费；`--full` 输出完整 prompt
- **输出直接带上 `imageLicense` 与「不可再分发」标记**，取用时不必再回头查授权表

实测（本地与发布包两种布局都跑通）：

```
$ node 04_工具\检索.mjs styles bloom --limit=1
  Anamorphic Lens Flare（Anamorphic lens flare）  [atlas-anamorphic-lens-flare]
    分类 2000 年代   来源 atlas
    主图授权 版权保留（不可再分发）
    参考图 风格参考图/风格图鉴_anamorphic-lens-flare.webp
    出处 https://atlas.letz.ai/effect/anamorphic-lens-flare
```

### 7.4 发布包新增 `skill.md`（给 Agent 的说明书）

做法参照 atlas 官方（<https://atlas.letz.ai/skill.md>，它也是「公开只读 API + 一份 skill.md」的形态），
写清四件事：

1. **数据在哪** —— 相对仓库根的路径（`data/`、`assets/`、`tools/`），不需要联网、不需要起服务
2. **怎么检索** —— 首选 `tools/检索.mjs`，HTTP 作为备选
3. **哪个字段干什么** —— 三库字段速查（含动效库的 `timing`/`easing`/`amplitude` 三段与 `whitened.slots`）
4. **授权红线** —— 逐条判读结论 + 「`imageRedistributable: false` 的不要外发」+
   「不要删 motion-prompt 元素代码的首行授权注释」

还带一节「边界」：不要编造条目里没有的参数、不要把规格卡当渲染预览描述给用户、
改写版要另行标注不要混进原文。

装法（README 里也写了）：

```bash
cp skill.md <agent-skills-dir>/style-atlas/SKILL.md
# 或直接在提示里贴给 Agent：读取本仓库的 skill.md 并按它工作
```

### 7.5 顺带修的一个文档问题

`素材调用说明.md` 讲的是**本地素材库**的路径（`03_索引\`、`02_素材\`），
与发布包布局不一致，所以**不进包**（一开始想拷进去，核对后发现会指向不存在的路径，已撤）。
包内的用法说明由 README 的「怎么用起来」一节 + 根目录 `skill.md` 承担。
