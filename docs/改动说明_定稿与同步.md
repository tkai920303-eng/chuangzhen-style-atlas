## 二、开源内容同步机制（新建）

素材库会持续增长，公开仓库必须能跟着长，且**每次发布都要能被验证**。分成两层。

### 2.1 本地侧：`04_工具\同步开源包.mjs`（新建）

一条命令跑完整条链路：

```
重新导出 → 包内 verify → 包内 smoke → 泄露扫描 → 与上一版逐文件比对 → 输出变更清单
```

| 参数 | 作用 |
|---|---|
| （无） | 完整链路，并把变更清单追加进 `06_开源包\变更记录.md` |
| `--dry` | 只比对，不改动任何文件 |
| `--no-verify` | 只导出 + 比对，跳过验收与泄露扫描 |
| `--snapshot-only` | 只给当前包打基线快照（给既有产物建立比对起点） |

配套产物放在 **包外**的 `06_开源包\`（不进包）：

- `发布快照.json` —— 上一次同步后每个文件的 SHA-256 + 体积
- `变更记录.md` —— 每次同步自动追加的变更清单，可直接摘抄成 release notes

### 2.2 每次导出自动写 `docs/同步状态.md`（进包）

把「包有多新」变成**可核对的事实**，而不是一句承诺：

| 项 | 值 |
|---|---|
| 导出时间 | 本次导出时刻 |
| 本地库索引时间 | `2026-11-23T04:06:02.265Z` |
| 本地库素材总数 / 作品数 | 146,564 / 302 |
| 本包三个库 | 风格 552 / 动效 370 / 光影 130 |
| 本包参考图 | 风格 568 / 动效预览 436 / 动效参考图 130 / 光影 53 |

### 2.3 包内 CI 的职责边界

包内 `.github/workflows/ci.yml` 能保证的是「**图鉴可重复生成**」（重新生成后 `git diff --exit-code`）。
它**不能**从公开仓库反向拉本地库——同步只能发生在本地。这是两层的分工，不是漏洞。

### 2.4 公开子集的口径

本地库 146,564 项 vs 发布包 1,237 个文件，**两者口径不同**：

- 本地库 = 全量索引 + 私有工程路径 + 第三方原片（不公开）
- 发布包 = 三个参考库 + 全部参考图 + 采集/构建脚本 + CI（公开子集）

README 里明确写清这一点，**不把「14 万项」说成全部开源**。

## 三、顺带修掉的 4 个真问题

### 3.1 泄露扫描把「占位符盘点」升级为发布门禁

原来「待人工替换的占位符」只是一行提示，**不影响退出码**——
包里有占位符照样「验收通过」。现在占位符残留直接让 `泄露扫描.mjs` 退出码为 1，
`同步开源包.mjs` 随之中止导出。占位符从「靠自觉」变成「过不了关」。

### 3.2 内容文件烧了生成时间戳 → 变更清单永远报假变更

导出时有三处写入了 `new Date()`：

- `data/atlas-image-credits.json` 的 `generatedAt`
- `data/third-party-exclusion.json` 的 `generatedAt`
- `docs/第三方素材剔除记录.md` 的「生成时间」

结果：**内容一个字节没变，diff 每次都报 4–6 个文件修改**，release notes 直接失去意义。
已去掉这三处时间戳，改为指向 `docs/同步状态.md`（运行状态只该在一个地方）。

实测效果：连续两次导出，第二次的变更清单**只有 `docs/同步状态.md` 一个文件**——它记录导出时间，属预期。

## 四、扫描器修正：`.mh` 运行时文件不入索引

### 4.1 现象

索引一致性校验报出 **2 条失效条目**——MotionHarness 会话目录下的 `session.json` 与 `writer.json`
（本机绝对路径随包分发时会被脱敏成 `<本机路径>`）：

```
<本机路径>
<本机路径>
```

查证：这两个文件**现在确实不在磁盘上**（`.mh` 目录里只剩 `export-state.json`、`preview.json`、
`recovery.json` 等）。它们是 MotionHarness 的会话状态文件，daemon 一重启就换名或删除。

### 4.2 为什么不能整目录排除

`.mh` 里有两个子目录是**真素材**，必须继续扫描：

| 子目录 | 内容 | 体积 |
|---|---|---|
| `.mh/exports/` | 5 个导出成片（mp4 / wav） | 115.12 MB |
| `.mh/objects/` | 64 个内容寻址块 | 125.58 MB |

### 4.3 采取的规则（窄口径）

`04_工具\scan.mjs`：**只排除 `.mh` 的直接子文件**，子目录照常扫描。

```js
// MotionHarness 运行时目录（.mh）的直接子文件是会话状态……
if (path.basename(path.dirname(full)) === '.mh') continue;
```

重扫后：索引条目全量校验**失效 0 条**。

## 五、校验脚本判据修正

`04_工具\校验索引一致性.mjs` 原判据是
「索引里不得出现任何文件名匹配 `西瓜.*_原片` 的条目」。

**这个判据是错的**，因为素材库会持续入库新的西瓜系列素材：

| 文件 | 磁盘状态 | 说明 |
|---|---|---|
| `<私有工程>_原片_1920x1080_32s.mp4` | 已删 | 11-19 被删 |
| `<私有工程>_原片_1920x1080_171s.mp4` | 已删 | 11-19 被删 |
| `<私有工程>_原片_1920x1080_199s.mp4` | 已删 | 11-19 被删 |
| `<私有工程>_原片_1920x1080_206s.mp4` | **仍在磁盘** | 本来就没删，重扫后重新收录是**正确**的 |
| `<私有工程>_原片_1620x1080_355s.mp4` | 在磁盘 | 11-22 之后新入库 |
| `<私有工程>_原片_1440x1080_153s.mp4` | 在磁盘 | 11-23 之后新入库 |

按名字正则判，会把**正常收录**误报成故障。已改为**按确切路径**判两条：

- 已删除的 3 条不再被索引收录（0 条残留）
- 已删除的 3 条在磁盘上确实不存在（磁盘 0 条残留）
